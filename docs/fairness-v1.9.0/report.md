# V1.9.0 席位公平与经营时机对照

四席共用人口概率、有限池及购买/刷新/经验规则。源码没有灯岚或其他命名席位的额外金币、经验、掉率或战斗加成。旧版存在固定商店发牌先后、备战开始即整批完成AI经营，以及重开复用相同种子的机制；V1.9修正这些机制，并随机分配三种经营风格。

## 方法

修改前与后各400局，使用相同种子范围1001–1400，四席全部托管并显式设置FLEX，移除人类操作熟练度及风格差异。测试入口关闭“真人淘汰即结束”，以完整决出每局冠军；实际应用保持该规则。每个固定逻辑步检查卡池份数、金币非负、人口/槽位/UID和真实参战配对守恒。

修改前数据在本轮代码修改前采集，修改后数据来自V1.9规则引擎。修改前继续至冠军的设置仅用于审计。保留[before.csv](before.csv)、[after.csv](after.csv)和原始日志；当前实现的复现入口为[scripts/SeatFairnessAudit.java](../../scripts/SeatFairnessAudit.java)。本轮没有重跑英雄数值锦标赛。

## 结果

| 席位 | 修改前冠军数/率 | 修改后冠军数/率 | 修改前交锋胜场/参战 | 修改后交锋胜场/参战 |
|---|---:|---:|---:|---:|
| 你（同策略托管） | 83 / 20.75% | 113 / 28.25% | 1874 / 3874 | 1967 / 3867 |
| 松隐 | 98 / 24.50% | 100 / 25.00% | 1933 / 3883 | 1876 / 3888 |
| 灯岚 | 99 / 24.75% | 96 / 24.00% | 1925 / 3858 | 1939 / 3883 |
| 赤砂 | 120 / 30.00% | 91 / 22.75% | 2031 / 3949 | 1952 / 3894 |

修改后四席冠军率范围22.75%–28.25%；400局里25%冠军率的单席抽样标准误约2.17个百分点。该结果没有支持“灯岚专属加成”或“灯岚一直赢”的判断。机制层的固定先取卡池问题已修正，但前后多项机制共同改变，不能把结果差异全部归因于某一项。

## 实现与限制

- 每局新种子；同一基础种子的完整重开序列仍可复现。
- 商店发牌起始席随机并逐轮轮换；四席各有独立商店内容，共享剩余池会使实际可抽概率受其他席位预留卡影响。
- AI首次动作等待2–4秒，再按0.8–2秒间隔执行购买、升级与最多两批刷新。没有免费补款；准备完毕先完成付费待办再锁定。
- 灵活经营、偏搜低费、偏升级每局随机分配，灯岚不固定拥有其中一种。
- 战斗期间真人可提前经营下轮，AI目前仍只在备战阶段自动经营；接口经济规则一致，操作策略与频率不必相同。

此审计是同策略席位对照，不是默认三个不同风格AI的强弱排序，更不是玩家真人胜率。不存在额外加成不代表任何抽卡结果或所有阵容都平衡；战斗技能强弱仍依赖V1.8的具体阵容与预算验证范围。

## 复现修改后审计

先执行`./gradlew :app:compileDebugKotlin`。令`KOTLIN_STDLIB`指向本机Gradle缓存中的kotlin-stdlib-2.0.21.jar，将输出放在已存在的临时目录：

```bash
javac -cp "app/build/tmp/kotlin-classes/debug:$KOTLIN_STDLIB" -d /tmp scripts/SeatFairnessAudit.java
java -Xmx2g -cp "/tmp:app/build/tmp/kotlin-classes/debug:$KOTLIN_STDLIB" SeatFairnessAudit /tmp/jade-fairness-recheck.csv 400
```

完整正常结束与人类淘汰冻结分别由100局默认AI和150局策略模拟验证，结果见[simulation-v1.9.0-100.md](../verification/simulation-v1.9.0-100.md)与[strategy-v1.9.0-150.md](../verification/strategy-v1.9.0-150.md)。
