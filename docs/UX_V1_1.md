# 青玉棋会 V1.1：佩戴体验修订

用户实际反馈：经营面板挡住棋盘和手柄/眼手操作路径；格数偏少；英雄过于像国际象棋；商店缺少图片；环境黑暗、没有装饰。

本次直接实施，不发起新的登录、充值或发布。

## 棋盘与面板

- 从 6×6 增到 8×8，共 64 格；己方可布阵区域从 3×6 增到 4×8。人口仍为 7，备战席仍为 8。
- 棋格间距拟为 0.23m，棋盘宽度 1.84m。场景保持 unbounded Stage，棋盘中心拟为 `(0, .82, -2.15)`。
- 正前方保留完整棋盘与备战席操作空间。经营面板移到左侧，商店拆到右侧，均采用有限高度的滚动内容；不让展开玩法或装备列表使面板向棋盘扩张。
- 初始布局：两侧面板中心拟为 `x=±1.46, y=1.35, z=-1.30`，朝向玩家；状态面板移至上方远处。上述为候选值，必须在实际 Attachment 包围盒可用后检查与棋盘视线/操作空间的交叉。
- 3 个 AI 棋盘和阵容摘要随主棋盘放大重新排布，避免与左右面板重叠。

## 操作

- 保留点选英雄再点格子的操作。
- 增加原生 Spatial drag，手柄和眼手使用同一规则入口。仅己方准备阶段、未暂停且未托管时允许拖动。
- 开始拖动只产生视觉预览；释放时才调用规则模块移动/交换。超出己方棋格与备战席、取消手势、人口已满、进入战斗或暂停时回到权威位置，不静默夹紧到最近格。
- 使用 SDK 的像素到物理长度转换。视图横向对应棋盘 X；视图纵向和深度映射到棋盘 Z，让向上拖动可进入较远棋格。不要把 rawPosition 当作已知世界米坐标。
- 成功和失败文案说明实际落点/原因。

## 英雄与商店

- 现有十二张生成参考图均提供商店缩略图，使用实际资源；名称、费用、阵营和近战/远程职业信息仍清楚可读。
- 近战强化盾、剑和宽肩轮廓；远程显示弓/弩/法杖及射击、施法动作区别。
- 去掉现有生成模型和开发造型的圆形国际象棋式底座。先量测、处理原始 GLB，再重新核验脚底、尺寸、贴图与朝向。
- 七个开发造型改为可分辨的躯干、头、四肢和武器形状；移动时采用低成本的身体/四肢摆动。五个静态生成模型采用位移、起伏和攻击姿态。
- 按上一轮核验可用 100 点，整套重生成及骨骼动画不够。本轮不提交新的收费 3D 任务，不把程序动作声称为生成的骨骼走路动画。

## 环境

- 已生成明亮青玉庭院 2:1 全景：`docs/environment/jade_garden_sky.jpg`。
- 采用官方天空球方案：单个向内可见的 UV 球 + Unlit 贴图，作为包裹玩家的天空背景。使用 GLB 资源加载，不依赖未证实的专用天空盒类或立方体贴图接口。
- 地面使用明亮石色，增加边缘石柱、绿植与少量灯笼等静态装饰，远离棋盘和手部通道。不靠堆积实时光源或阴影提升亮度。
- 使用统一的象牙、青玉、淡蓝和石色；保留原生 PicoTheme。

## 验证

- 棋盘规则使用统一的列/行定义，替换战斗镜像、站位、边界和 AI 布阵中的 6/3/5 等硬编码。
- 覆盖 32 格布阵、镜像、最外格、释放/取消/非法落点，以及预算不变；重新执行现有边界回归和 100 局模拟。
- 核验六个面板的静态/运行时语义、样式与实际包围盒；报告数值视线避让与视觉验证分别是否完成。
- 构建、模拟器基本交互/战斗、真机启动和资源日志验证。用户自行佩戴验证手柄、眼手与视觉，不要求截图。
- 真机更新前只读检查对局状态，避免不必要地打断用户操作；最终更新为明确的 V1.1 包。

## 实施后的布局证据

实际面板测量：经营 .416×.512m、商店 .376×.568m。默认候选位置不能通过保守的完整桌面/备战席射线通道约束，因此运行时自动外移至经营 x=-2.11215m、商店 x=2.08104m，y=1.35m、z=-1.30m 保持。在下一帧变换同步后，两边的内侧边缘分别为 -1.95757m / 1.94132m，通道检查 PASS。模拟器与真机均有数值证据，佩戴转头舒适性仍由用户实测反馈。

36 项 JVM 测试、100 局模拟、六面板静态/模拟器/真机语义检查均通过。详细边界和实际运行结果见 `docs/verification/DELIVERY_V1_1.md`。
