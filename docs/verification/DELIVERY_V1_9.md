# 青玉棋会 V1.9.0 交付记录

V1.9.0 / code14，公开Spatial SDK6.1.9，com.pico.miniautochess；已安装并启动于B3110（PB331XPGL6040019G）。

## 修改

- 战斗及结算阶段开放备战席移动/交换/出售、买牌、刷新、买经验；上场阵容锁定。
- 购买只合成备战席副本；涉及上场副本的合成和新增人口补位在下一轮备战执行，不能改当前Battle/Fighter。
- 原生居中终局弹窗显示胜利/失败、名次与胜场，提供“再来一局”“退出”；退出关闭Stage。
- AI首步延迟2–4秒，后续0.8–2秒，分四步完成购买、升级、两批刷新。提前准备完毕时先付费完成待办经营再锁定。
- 首轮商店起始席随机、每轮轮换；三个AI风格每局随机分配，每次重开换新随机种子。
- 继承V1.8英雄数值、真人淘汰立即终局、一次结算、三人镜像、拖动高亮及原资源。

## 验证

完整构建成功，112项测试0失败/错误/跳过。新增7项战斗经营、3项AI时机/重开/终局回归。实验API与摆放源码门禁通过。摆放扫描的既有containment/detail-depth提示保留；未改变几何，启动日志数值检查通过。

席位公平对照修改前/后各400局，四席同为FLEX，种子1001–1400，测试模式允许真人死亡后继续决出冠军。修改前四席冠军数83/98/99/120，修改后113/100/96/91；灯岚99→96，即24.75%→24%。每步检查卡池、金币、人口与真实配对守恒，未发现命名席位专属经济/概率加成。此对照不等于普通真人胜率，也不证明所有策略强度一致。

100局当前默认AI与150局三策略模拟通过卡池/金币/人口/配对、真人死亡立即终局与终局冻结检查。本轮未重新运行V1.8数值锦标赛；历史英雄平衡数据保留，并明确标记为继承证据。

安装回拉base.apk与构建SHA-256一致。场景加载16模板、5正式模型；累计前移.30m、模型.85、桌面高度.265m，商店/备战席分离与40拖动槽位检查通过。启动窗口AndroidRuntime/crash缓冲无记录；SDK SpatialPack错误标签原始日志保留。

SDK6.1.9不支持Spatial AccessibilityComponent，源码审计仍有2个既有Attachment未解析；原生Compose语义保留，空间无障碍未通过，运行时审计原始失败结果保留。没有收费3D资源。没有截图验证；佩戴时的居中弹窗、射线拖动与实际经营体验由用户确认。安装/启动/源码与规则测试不能替代真机交互或帧率实测。

## 佩戴确认

1. 开战后买牌、刷新、买经验；本场人数/星级/站位应保持不变，备战席可出现新棋子和合成。
2. 拖动备战棋子交换或移位、拖到商店出售；上场棋子不可拖或出售。
3. 下一轮备战开始后，涉及上场副本的合成及升级新增人口补位生效。
4. 真人淘汰/夺冠时居中弹窗显示失败/胜利；再来一局重置状态并换卡，退出关闭棋会。
