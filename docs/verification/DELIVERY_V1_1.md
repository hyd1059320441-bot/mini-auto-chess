# 青玉棋会 V1.1 交付验证

用户佩戴反馈：正前方 UI 挡棋盘和拖动路径，棋格少，英雄像国际象棋，商店缺图片，环境黑暗。

## 实现范围

- 主棋盘 8×8，己方四排 32 格；间距 .23m、棋盘宽 1.84m。人口保持 7，备战席保持 8。所有站位、战斗镜像、边界与 AI 布阵共用规则定义。
- 左侧经营 520×640dp，右侧商店 470×710dp，固定高度滚动。状态面板位于上方远处，AI 小棋盘与摘要移至更远处。
- 原生 Spatial drag 支持手柄与眼手，像素增量通过 SDK 转为米。按住时仅移动视觉预览，释放才调用一次规则移动；取消、敌方半场、超出棋盘、满人口、暂停、托管、阶段切换或源棋子改变均取消预览，不静默夹紧。原有点选再点格保留。
- 现有五个生成模型按实际截面裁去圆形底座，UV 保留，原始资源不变。七个程序英雄改为躯干、头、四肢和职业武器，加入移动摆动、近战挥击与远程动作。五个生成模型仍为静态网格，不声称新增骨骼动画。
- 商店十二张 320×320 图片来自实际生成的英雄参考图，附姓名、费用、阵营和近战/远程职业信息。
- 明亮庭院 2:1 天空贴图、向内 UV 球、象牙石地、青玉绿植和陶红灯笼；不增加实时灯光和阴影。
- 本轮收费 3D 任务为 0，没有重复 SGS 生成、登录、余额查询、充值或发布。

## 规则与静态检查

- 36 项 JVM 测试全部通过：31 项经济/对局/拖动测试、4 项格子映射/镜像/边界测试、1 项 100 局模拟。
- 100 局正常速度逻辑模拟全部终局，499.5–639.0 秒，中位 558.1 秒，100/100 在 8–12 分钟；1934 场战斗含 134 场 Ghost。英雄池、金币、人口、位置唯一性及配对约束通过。
- 样式检查：0 错误、0 警告。六色值与原生 PicoTheme 保留。
- 六个面板语义 inventory / contract / project-audit：6/6，0 错误、0 警告。
- Placement source gate PASS。单条 containment advisory 为启发式检查没有识别命名 owner/epsilon；项目是 unbounded Stage，生成英雄有模板坐标下的实际尺寸/脚底检查，面板有独立测量与通道约束，不作全局包围盒 fit 的声明。

## 运行时测量方法

当前 SDK 的 Attachment `getVisualBounds` 返回空值。使用面板自己的 Compose `onSizeChanged` 测量像素尺寸，以该面板 `LocalPhysicalLengthConverter` 换算为米，四角通过公开 `Entity.convertPositionTo` 转入 owner 坐标，得到旋转后的 AABB。

以头部横向 ±.15m、桌面半宽 1.02m、最近前沿 .84m 为保守水平视线/射线锥，留 .06m 额外间隔。侧面板边缘不足时向外移，并在下一次帧同步后复核，避免拿旧变换缓存宣称调整通过。该数值约束不等同于佩戴舒适性验收。

## 验证边界

六个 UI 面板属于语义合同范围；3D 棋子与棋格使用原生碰撞、Interactable 和指针手势，未宣称全场景屏幕阅读器支持。用户自行佩戴核验手柄/眼手实际落格、环境观感与转头舒适性，不要求截图。没有以模拟器或规则模拟宣称真机达到 90 FPS。

## 天空材质的最终修正

交付打包核对中发现，trimesh 将整数 `[1,1,1,1]` 理解为 8-bit RGBA，天空球实际 GLB 材质导出了约 .00392 的乘色与透明因子。已修正为完整白色/不透明。生成器和 APK 打包器直接读取实际 GLB JSON，并断言 `[1.0,1.0,1.0,1.0]`，防止加载成功但显示发黑的问题。六个应用 GLB 的该因子均确认完整白色。

修正版先在模拟器安装启动。用户随后明确要求立即安装真机，已取消等待终局的后台任务，并将最终 `dist/jade-chess-v1.1-preview.apk` 安装、启动于 B3110（PB331XPGL6040019G）。设备记录更新时间为 2026-11-07 14:41:51；新进程确认天空环境、12 个英雄模板和音效初始化成功，两侧面板通道 PASS。最终证据见 `device-sky-fix-startup.log`。
